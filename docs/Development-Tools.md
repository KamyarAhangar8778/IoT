# راهنمای ابزارهای توسعه، کیفیت کد و تحلیل استاتیک (Development & Toolchain Guide)

این مستند راهنمای جامع ابزارهای فرمت‌بندی، تحلیل استاتیک، کامپایل و پروفایلینگ حافظه برای فریم‌ورک ESP32 در پروژه **Achaemenid IoT** است.

---

## ۱. ساختار جعبه‌ابزار توسعه (Toolchain Stack)

برای تضمین کیفیت، پایداری سخت‌افزاری و سرعت اجرای فریم‌ورک C++، پنج ابزار استاندارد صنعتی در پروژه تعبیه و پیکربندی شده‌اند:

1. **PlatformIO Core CLI (`pio`):** کامپایلر رسمی، مدیریت کتابخانه‌ها و بیلد سیستم بدون وابستگی به محیط گرافیکی.
2. **`clang-format` (نسخه 14):** یکپارچه‌ساز ظاهر و ساختار کدهای C/C++ بر اساس فایل `.clang-format`.
3. **`cppcheck` (نسخه 2.10):** تحلیل‌گر استاتیک برای کشف خطاهای منطقی، متغیرهای مقداردهی‌نشده، نشت حافظه و باگ‌های نهفته.
4. **`clang-tidy` (نسخه 14):** لینتر پیشرفته LLVM برای ارزیابی الگوهای مدرن C++17 و استانداردهای طراحی.
5. **Firmware Size & Memory Profiler (`scripts/size-esp.sh`):** تحلیل‌گر تفکیکی مصرف سگمنت‌های حافظه SRAM (DRAM/IRAM) و Flash.

---

## ۲. دستورات خط فرمان (`package.json`)

تمامی ابزارها از طریق اسکریپت‌های npm در ریشه پروژه قابل اجرا هستند:

| دستور | شرح عملکرد | ابزار پشتیبان |
|---|---|---|
| `npm run compile:esp` | کامپایل کامل فریم‌ورک ESP32 | PlatformIO Core (`pio run -d .`) |
| `npm run format:esp` | اصلاح خودکار فرمت تمام فایل‌های `.cpp` و `.h` | `clang-format` |
| `npm run format:esp:check` | اعتبارسنجی رعایت فرمت بدون ایجاد تغییر در فایل‌ها | `clang-format --dry-run` |
| `npm run lint:esp` | اجرای تحلیل استاتیک عمیق | `cppcheck` |
| `npm run tidy:esp` | تحلیل الگوها و قوانین مدرن C++ | `clang-tidy` |
| `npm run size:esp` | اندازه‌گیری بایت‌به‌بایت مصرف حافظه Flash و RAM | اسکریپت اختصاصی Profiler |
| `npm run check:esp` | اجرای همزمان اعتبارسنجی فرمت و لینتر استاتیک | ترکیب `format:esp:check` و `lint:esp` |

## ۳. استانداردهای کدهای C++ در فریم‌ورک ESP32

در هنگام توسعه یا ریفکتور کدهای پوشه `ESP-CODE-S/`، رعایت اصول زیر الزامی است:

### ۱. تبدیل صریح نوع (Explicit Type Casting)
کامپایلر با استاندارد C++17 و فلگ‌های سخت‌گیرانه اجرا می‌شود. تبدیل ضمنی بین `uint8_t` و انواع شمارشی (Enum مانند `wl_status_t`) ممنوع است و باید با `static_cast<...>` انجام شود.

### ۲. صفردهی متغیرهای عضو (Zero Uninitialized Member Variables)
هیچ متغیری نباید در بدنه سازنده بدون مقداردهی رها شود (`uninitMemberVar`). برای آرایه‌ها در کلاس از براکت تهی `{}` در Initialization List استفاده کنید:
```cpp
// نمونه صحیح
class PinStateManager {
    PinStateManager(PinRegistry& reg) : _registry(reg), _inputIndices{}, _numInputs(0) {}
};
```

### ۳. استفاده از عملگرهای پیشوندی (Prefix Operators)
در کانتینرهای اختصاصی و کلاس‌ها، همواره عملگرهای `++i` و `--i` را بر `i++` ترجیح دهید تا از ساخت اشیاء موقت در حافظه جلوگیری شود.

### ۴. سازگاری متون چندزبانه در فرمتر
فایل `.clang-format` دارای گزینه `BreakStringLiterals: false` است تا رشته‌های حاوی متون فارسی (UTF-8) در زمان فرمت‌بندی شکسته نشوند.

## ۴. تاریخچه باگ‌های کشف و رفع‌شده با تحلیل استاتیک

در بررسی جامع کدهای فریم‌ورک با `cppcheck` و `clang-tidy` موارد زیر شناسایی و برطرف شدند:

1. **`PinStateManager.h`:** آرایه ایندکس ورودی‌ها `_inputIndices[MAX_PINS]` بدون مقداردهی بود که با `_inputIndices{}` صفر شد تا از مقادیر زباله در رانتایم جلوگیری شود.
2. **`Executor.h`:** آرایه `active_futures` در سازنده بدون مقداردهی اولیه به `nullptr` بود که اصلاح شد.
3. **`FastFunctionCopyMove.h`:** انتقال `storage_` از بدنه سازنده Move به لیست مقداردهی اولیه سازنده جهت جلوگیری از کپی موقت.
4. **`StaticHashMapStringImpl.h`:** تبدیل پسوندی به پیشوندی برای متغیر شمارنده اسلات‌های هش‌مپ.
5. **`logging.h`:** قرار دادن پارامتر ماکرو `level` در پرانتز `(level)` برای جلوگیری از خطای تقدم عملگرها.
6. **`ESP32WiFiAdapter.h`:** افزودن `static_cast<wl_status_t>` به خروجی `wifiMulti.run()`.

## ۵. راهنمای تحلیل حافظه (Size & Memory Profiling)

برای جلوگیری از سرریز حافظه، پس از هر بار کامپایل دستور زیر را اجرا کنید:
```bash
npm run size:esp
```
این اسکریپت بخش‌های زیر را تفکیک می‌کند:
- **`.dram0.data` & `.dram0.bss`:** متغیرهای سراسری و استاتیک در RAM (محدودیت کلی: ۳۲۰ کیلوبایت).
- **`.iram0.text`:** کدهای بحرانی و روتین‌های وقفه در RAM برای اجرای فوق‌سریع.
- **`.flash.text` & `.flash.rodata`:** کدهای اصلی برنامه و داده‌های فقط خواندنی در حافظه Flash (حداکثر ۱.۹ مگابایت بر اساس پارتیشن `min_spiffs.csv`).
